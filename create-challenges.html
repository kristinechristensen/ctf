01 / Step-by-step instructions

Build your first challenge in the CTFd Admin Panel

  1. Open your local CTFd server in Firefox (typically http://localhost:8000). Log in as administrator.
  2. Go to Admin Panel → Challenges and select New Challenge / +.
  3. Select the Standard challenge type. Enter the Name, Category, Description, and Value (points).
  4. Use the Options dialog to enter a Static flag, choose case sensitivity, attach any files, and set the challenge to Visible when ready.
  5. Select Finish. Edit the challenge to add or adjust Hints, Files, and Solution content. Recommended solution release: after solve.
  6. Keep the description focused on the task, not the answer. CTFd automatically displays the challenge name, so don't repeat that title as a description heading.
  7. Open a Firefox Private Window with Ctrl + Shift + P. Sign in as a separate test participant, open the challenge and submit the correct flag.
  8. Return to Admin → Submissions / Scoreboard. Verify accepted flags, point awards, hints, files and solution visibility.
Where does each part go? Description = instructions; Flags = accepted answer; Hints = scaffolding; Files = evidence/starter code; Solution = explanation, generally released after a solve.

02 / Reusable template

Start from a good learning objective

Design questions

What skill does the activity assess? What evidence must learners interpret? How will they know they have succeeded? What hint helps without revealing the flag?

Recommended first setup

Standard points; one exact static flag; an accessible text description; a free hint; a post-solve solution; visible state when tested.

For downloadable files

Place only the student-facing artifact in the Files area, such as a log, CSV, or Python script. Keep instructor solutions in the admin Solution tab.

03 / Copy-ready examples

Five complete examples across disciplines

01 · Welcome to the Flag Hunt

Getting Started · 10 pts · Beginner
Description
Welcome! Capture your first flag by entering the following training flag exactly as written: CTF{Welcome2026}.
Flag
CTF{Welcome2026}
Hint (0 points)
The flag is displayed in the challenge instructions.
Solution: visible after solve
The participant enters the supplied practice flag, learning the submission format and where points appear.

02 · Spot the Phish

Cybersecurity · 25 pts · Beginner
Description
A message claims to be from your college IT team. Sender: IT Support <helpdesk@college-security-alert.com>. Subject: URGENT: Account access suspended. The message asks you to verify your account at https://college-security-alert.com/verify within 30 minutes. Identify the suspicious sender domain and submit it in the standard CTF flag format. Do not visit the link.
Flag
CTF{college-security-alert.com}
Hint (0 points)
Inspect the address after the @ symbol. Does it match the organization claimed by the message?
Solution: visible after solve
The sender domain college-security-alert.com is not the college’s official domain. The urgency and request for credentials add warning signs. A domain mismatch is a clue, not proof alone.

03 · The Connection Problem

General IT · 50 pts · Beginner
Description
Staff can reach a server but cannot connect to its secure web application. Server: 192.168.10.50. Ping: replies received. TCP 80: connection succeeded. TCP 443: connection refused. Identify the TCP port that is not accepting connections. Submit the number using the standard CTF flag format.
Flag
CTF{443}
Hint (0 points)
Compare the two TCP connection tests. Which test returned “connection refused”?
Solution: visible after solve
TCP 443 refused the connection. Ping demonstrates basic IP reachability but does not prove that a specific TCP application is running. A refusal may indicate no listener or an active reject.

04 · Who’s Knocking?

Cybersecurity · 75 pts · Intermediate
Description
Download the provided authentication.log file. Review SSH login events. Identify the source IP that produced repeated failed login attempts followed by a successful login. Submit the IP address in the standard CTF flag format.
Flag
CTF{198.51.100.77}
Hint (0 points)
Search for “Failed password,” then compare that source with the “Accepted” events.
Solution: visible after solve
The suspicious source IP is 198.51.100.77. Repeated failures followed by a successful SSH authentication warrant investigation, but this pattern alone is not proof of compromise.

05 · Follow the Code

Computer Science · 100 pts · Intermediate
Description
Trace this Python code without changing it:

numbers = [4, 7, 2, 9]
score = 0
for index, number in enumerate(numbers):
    if number % 2 == 0:
        score += number * 2
    else:
        score += index
print(score)

Submit the final printed integer using the standard CTF flag format.
Flag
CTF{16}
Hint (0 points)
Track score after each iteration. List indices begin at zero.
Solution: visible after solve
At indices 0–3, the score changes to 8, 9, 13, then 16. The final printed integer is 16.

File-based upgrade: For “Who’s Knocking?”, use the challenge library or create an authentication.log file containing the sample SSH events. Remove the log from the description and add the file using CTFd → Challenge → Files. Confirm the participant can download it.
